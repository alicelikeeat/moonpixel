# 测试结果与未验证事项

## 核心逻辑测试

命令：`cd ios && swift test -c release -Xswiftc -enable-testing`
环境：Linux x86_64，Swift 工具链（CI 另在 macOS 上运行同一套测试）。
结果：**44 个测试全部通过**，耗时 82 秒。

| 验收项 | 测试 | 实际数据 |
| --- | --- | --- |
| 三国自动经历发展、开战、休战、统一、分裂 | `RealmTests.testThreeKingdomsCycleAndHysteresis` | 种子 7、默认参数、无玩家，34 年内：9 次战争、3 次休战、13 次占领、4 次城镇倒戈、90 次随机事件、1 次统一、1 次分裂；结束时 110 人、8 座城、三国科技均为 9 级 |
| 人口与战争阈值有效，不会连续开战休战 | 同上；`testThreeNationsWithLandAndPressureFromFoodHousingJobsLand` | 同一对国家休战后到下次开战的间隔均不小于最短休战期 + 冷却期；人数不变而断粮、无房时压力明显上升 |
| 统一后认同保留，到期恢复三个有领土的国家 | `testUnificationKeepsIdentityAndEndsInThreeLandedNations` | 统一在期限内结束；三国各有领土；没有新增移民；科技和建筑保留；分裂后以休战开始 |
| 事件可复现、有冷却 | `testEventsAreSeededConditionalAndCoolDown`、`testLeaderSuccession` | 相同种子两次运行日志完全一致；同一国家的同类事件间隔不小于冷却期 |
| 远近模拟结果一致 | `testCameraDoesNotChangeOutcome` | 有无“镜头观察”两次运行的完整状态摘要逐行相同 |
| 玩家行动改变补给、战线和关系 | `PlayerTests`（2 个） | 铺路架桥后补给上升超过 0.1，补给站再加 0.15 且只对本国有效，拆除后恢复；补给 1.0 的军团战力是 0.3 时的两倍以上；击杀使军团真实减员、对方疲劳上升、关系下降；捐赠增加存粮和好感；接纳难民改变城镇人口 |
| 四种法则真实释放数据 | `LawTests`（灭霸、湮灭、归墟、创世纪各 1 个） | 灭霸恰好删除一半并使人物数据缩小三分之一以上；湮灭和归墟后区块文件实际被删除；创世纪后旧区块文件数为 0 |
| 相同快照、配置、种子产生相同删除计划 | `testThanosDeletesHalf…`、`testAnnihilationByRatioAndBySpace`、`testGuixu…` | 计划对象逐项相等；换种子则不同 |
| 删除、统一、分裂后无悬空引用，重载一致 | 各测试中的 `audit()`；`testThreeKingdomsCycleAndHysteresis` | 34 年后引用检查为空；存档重载后的状态摘要与保存前逐行相同 |
| 中断、共享素材 | `testInterruptedLawIsFinishedFromItsJournal`、`testSharedAssetsSurviveUnsharedOnesAreFreed` | 执行到一半“被杀掉”，用旧存档加日志重放后结果与完整执行一致；重放已完成的计划不再删除任何东西；仍被引用的共享素材保留 |
| 无人存活进入文明重启 | `testEveryoneGoneMeansAnExplicitRestart` | 状态变为重启；等待期内人口为 0；之后以三国重新开始 |
| 容量策略 | `testStoragePolicyOnlyDestroysWhenThePlayerChoseIt` | 缓存优先从不删除；自动策略只在超过高水位且冷却结束后触发 |
| 多次重置后资源不持续增长 | `testRepeatedLawsDoNotGrowResources` | 6 轮灭霸/归墟交替后占用（字节）：497978 → 502461 → 442464 → 418443 → 412797 → 326102；区块缓存 34 → 18 |

## 性能数据（实测）

| 项目 | 数据 | 环境 |
| --- | --- | --- |
| 核心模拟 600 次更新（120 名居民、4 座城） | 0.188 秒，约 0.31 毫秒/次 | Linux x86_64，release |
| 2000 次寻路 | 0.44 秒 | 同上 |
| 34 年三国模拟（含战争、统一、分裂） | 44 秒，约 20400 次更新 | 同上 |

以上是核心逻辑在开发机上的耗时，不是设备帧率。**没有测量过真机帧率**，“稳定 60FPS”目前没有数据支持，也没有在模拟器里测帧率（模拟器的数值不能代表真机）。

## 未验证事项

- **真机**：没有在任何真实 iPhone 上运行过。触摸、性能、发热、内存警告处理、照片库权限流程都只在模拟器里走过。
- **帧率**：未测量。
- **空间不足**：保存失败的提示和“旧存档保持完好”依赖原子写入，代码路径已实现，但没有在真正写满的磁盘上测试过；测试只覆盖了日志损坏和中断重放。
- **App 层的法则流程**：删除计划、分批执行、日志恢复在核心层有测试；App 层（保存 → 写日志 → 执行 → 清理素材 → 保存 → 删日志）只由模拟器界面测试走通正常路径，没有在 App 里模拟过中途被杀。
- **异步照片任务作废**：切换世界、目标被删除、创世纪后丢弃结果的判断已实现，没有自动化测试。
- **自动容量策略**：决策逻辑有测试；在 App 里按水位自动触发没有实际跑到过（需要把世界写到上限附近）。
- **Vision 人脸识别和人像分割**：模拟器里用合成图片测试，没有用真实照片和真实视频验证效果。
- **长时间运行**：最长的自动化运行是 34 游戏年（约 44 秒计算）；没有做过数小时的真机连续运行。
- **默认参数下统一的频率**：只验证了种子 7。其他种子可能更早、更晚或在几十年内不出现统一。
- **湮灭的摆件统计**需要读取所有已保存的区块文件，地图很大时这一步可能较慢，没有在大存档上测过耗时。
