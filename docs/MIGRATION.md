# 迁移说明

## 技术路线

Godot 工程已完全移除，仓库只剩 Swift 一套技术栈。

| 已删除 | 说明 |
| --- | --- |
| `project.godot`、`export_presets.cfg`、`icon.svg*` | Godot 工程与导出配置 |
| `game/`、`tests/` | 全部 GDScript 脚本与 Godot 测试 |
| `tools/*.gd`、`tools/gd.sh` | Godot 专用工具 |
| `.github/workflows/ci.yml` | Godot 的 Linux 测试流程 |
| `content/` 下的 enemies、items、npcs、quests、recipes、skills、structures | 只有 Godot 版本使用的数据 |
| 旧 `docs/` | 描述 Godot 架构的文档 |

保留的通用数据：`content/tiles/tiles.json` 和 `content/biomes/biomes.json`，由 `tools/gen_swift_content.py` 生成
`ios/Sources/MoonPixelCore/ContentData.swift`。修改 JSON 后重新运行该脚本。

CI 只剩 `.github/workflows/ios.yml`：核心测试 → 真机编译 → 未签名 ipa → Release → 模拟器截图与界面测试。

## 存档兼容

旧存档可以直接打开，新增字段全部是可选的：

- 没有三国数据的存档：打开时按地理位置把现有城镇分给三个国家，居民获得所在城镇的国家认同。
  城镇少于三个时，没有领土的国家处于流亡状态，之后由现有居民迁出建城复国，不会凭空增加人口。
- 旧存档的全局科技等级成为三个国家共同的起点。
- 事件日志现在随存档保存（以前不保存）。
- 存档读取失败时，原文件另存为 `index.corrupt-<时间>.json`，不会被新存档覆盖。
- 世界法则执行期间目录里有 `law-journal.json`（只含删除计划，不含被删数据），提交成功后删除；
  打开世界时如果它还在，会先把这次法则执行完。

存档目录：`Documents/worlds/<id>/`。v1.6 起改为分代提交的存储，见下文“v1.6 起的存档格式”。

## 行为变化

- 科技从全局改为按国家研究；界面显示最先进国家的水平。统一时代三国共享已掌握的科技。
- 一句话创建世界时村庄数最少为 3（三国各需要一座城）。
- 武器不再只有视觉效果：命中、伤害、冷却和死亡由核心逻辑结算。新增斧和镐，可采集资源、拆毁道路桥梁和补给站。
- 城镇标签和地图上的城镇点按国家着色；士兵头顶有国家颜色的小旗。
- 存储上限可在世界法则面板里设为 50 MB / 500 MB / 1 GB / 5 GB（默认 5 GB）。

## 1.1 起的变化

- 版本号由 CI 自动递增：每次发布依次为 1.1、1.2、1.3……，Release 标签为 `v1.N`，安装包名为 `MoonPixel-1.N-unsigned.ipa`。
- 新增的存档字段（国家掌握的能力、科技树、天气、动物、玩家的专注/神器/伴侣/花、村民的娱乐需求和恋爱对象）全部可选，旧存档可直接打开；科技树在第一次需要时按世界种子生成。
- 世界生成新增迷宫：每 6×6 区块中有一个区块可能是迷宫。已保存（被修改过）的区块不受影响；旧世界里尚未修改的区块重新载入时可能出现迷宫。
- 村民不再一见钟情：互有好感后先相恋约十分之一年再结为伴侣。

## 1.3 的变化

- **存档格式号**：`index.json` 新增 `format`（1.3 为 3）。打开格式号更低（或没有格式号）的存档时，先把原文件复制为 `index.v2-backup.json`，再迁移，并提示玩家。解码失败的存档另存为 `index.corrupt-<时间>.json`，不会被覆盖。
- **配置宽松读取**：`RealmConfig` 中任何旧存档没有的参数都使用默认值（1.2 存档此前会因此打不开，已修复并有测试）。
- **新增的可选字段**：城镇的物资、生产进度、暂停原因、城市名、是否玩家所建、曾为哪国首都、围城军团、旗帜归属；国家的首都、迁都计划；军团的士气、军粮、器械、城墙耐久、围城阶段、路线、补给车队；居民的兵种；玩家的背包物资、建造计划编号、制造任务、所在层；纪事与事件编号。迁移后一小时内各国自动定都、纪事开始记录、旗帜按归属重染。
- **地下层**单独存放在世界目录的 `chunks_d1/`；归墟会把对应区块的地下部分一起恢复，创世纪会删除整个地下层。
- **事件**改用递增编号判断新旧，不再依赖日志条数（日志被裁剪时会漏报或重报）。
- **行为变化**：开拓队只带同城的家人（修复了配偶在另一城时留下悬空引用的问题）；实验室和 AI 中心的人口门槛由 16/18 降为 14；首都在大多数人有房后优先建王宫；行军路线按逐格寻路，桥和道路会被利用，没有路时军队涉水、补给降低。

## v1.6 起的存档格式（分代提交）

旧的 `index.json` + `chunks/` + `chunks_d1/` 改为一个按代提交的存储（`ios/Sources/MoonPixelCore/Store.swift`）：

```
Documents/worlds/<id>/
  HEAD                    当前代号（原子替换）
  gen/g<N>.json           第 N 代清单：每个区块、索引、meta 指向哪个对象
  objects/xx/<hash>-<size>.bin   内容寻址、只写一次的对象（区块、索引、meta）
  meta.json               世界列表用的摘要（可丢失，丢了不影响存档）
  assets/                 导入的图片与头像（不变）
```

- **一次保存是一代**：地表区块、地下区块、索引和 meta 写进同一代。先写对象并逐个校验，再写 `g<N>.pending.json`，然后原子替换 `HEAD`，最后把清单改名为 `g<N>.json`。没变的区块直接沿用上一代的对象，不重复写。
- **任何一步失败或中途被杀**：打开时读到的要么是完整的旧一代，要么是完整的新一代，不会混合。`HEAD` 损坏或某个对象缺失时，回退到 `HEAD` 以下最近一个校验通过的代，并提示“存档第 N 次不完整，已回到第 M 次”。从未切换 `HEAD` 的清单不会被当成存档。
- **清理**：保留当前代和上一代；执行永久删除类法则（灭霸、湮灭、创世纪、归墟）并保存成功后，只保留当前代，旧对象一并删除，被删的数据不会留在上一代里。清理失败或被打断不影响当前代，可以重复执行。
- **旧存档迁移**：第一次打开 v1.6 之前的存档时，把 `index.json`、`chunks/`、`chunks_d1/` 原样复制成第 1 代，**原文件不动，就是备份**。迁移失败则世界不打开、原文件不改。
- **格式号**：`index.json` 内的 `format` 在 v1.6–v2.5 为 3，v2.6 起为 4（见下文）；存储清单的 `format` 为 3。打开比当前版本更新的存档会被拒绝并提示更新，不会改写它。索引解码失败时原内容另存为 `index.corrupt-<时间>.json`。
- **法则日志**：`law-journal.json` 现在记录执行前的代号 `baseGen`。打开时：代号未变 → 重放；已经提交过 → 只删日志，不会执行两次。
- **退出到世界列表**：先保存，保存失败时世界保持打开并暂停，显示原因和“重试 / 留在这里”，成功后才释放。

## v1.6 起新增的可选字段

全部可选，旧存档可以直接打开：

- `realm.ledgerBox`：阵亡账本（每国阵亡总数、最近 48 场战斗各方损失）。旧存档从 0 开始记。
- `realm.contribBox`：玩家贡献记录与去重键。
- 军团：`routeStatus`、`routeDeps`、`routeGoal`、`routeT`、`routeFails`、`routeFailT`，补给车队的 `convoyStart`、`convoyTrip`、`escortT`、`escortThreat`、`raidT`。旧存档的军团第一次行动时重新规划路线。
- 建筑：`style`（建造它的国家，屋顶按它画）。旧存档没有这个字段的建筑按城镇当前归属画屋顶。
- 城镇的 `usedSlots` 现在按排序后的数组保存（读取时与旧格式相同），同一个世界总是写出同样的文件。

## v1.6 起的行为变化

- **行军**：路线只走合法地面（道路、桥、开阔地、林地、浅水）；深水、悬崖、墙和关闭的城门不能穿过，不再“直线涉水”。路线状态为完整 / 部分 / 需要攻城 / 需要桥 / 不可达；被挡住的军队等待后重试（30 秒起倍增），4 次后撤回或就地解散。桥、城门、墙一变，经过那里的路线自动重算。
- **模拟步长**：每档速度用固定步长（1× 为 1/60 秒，4× 为 1/15 秒，16× 为 0.25 秒，64× 为 1 秒），追不上的时间被丢弃并显示实际速度，不再用一个大步补。
- **城镇重任务**：大量城镇同时到期的规划和资源扫描分摊到后续几步。
- **城市布局**：军营、瞭望塔、要塞朝向最近的敌城；农业城的农田在外圈；市场和王宫在广场；地标的门朝向城中心，门后不放东西。
- **士兵绘制**：同屏士兵按 50 / 100 / 200 / 400 档绘制，只画真实士兵，前线优先，其余在军旗旁显示“+N”。
- **攻占**：旗帜在受损之前就换成新主人的；建筑和屋顶保持原建造国的样式。

## v2.6（存档格式 4）

- **为什么升格式号**：v2.6 新增旅人的身体（`player.body`）、背包状态（`player.invBox`：装备、快捷栏、地上的东西、饥饿、命令记录）、外置电梯（`realm.liftBox`）、立在附近的塔楼（`realm.standing`）、实际建过东西的楼层列表（`realm.storeySet`）、借出士兵的部队编号（`agent.lent`、`force.lentTown`）、塔楼的 `realLift`。这些字段全部可选，v2.6 能打开所有旧存档；但 v2.5 会忽略它们，下次保存就会丢掉。格式号 4 让 v2.5 及更早版本拒绝打开 v2.6 的存档，而不是读一半。
- **迁移**：打开格式 3 或更早的存档时，先把当前一代固定为 `gen/backup-v<n>.json`（连同它引用的全部对象），之后的每次清理都保留它；执行永久删除类法则并保存后，备份一并删除。再次打开不会重复备份。
- **旧存档的默认值**：没有身体时，旅人站在保存的位置和层的楼板上；没有背包状态时，没有装备、快捷栏为空、饥饿 0.2；没有楼层列表时，按旧规则视为 1…最高层（旧存档的楼层都很低），之后只记录实际建过东西的层。
- **v2.5 建出的 40 层塔楼**：它们是真实的方块，原样保留；同一座塔楼在 v2.6 中不会再被建一次（`real` 标记仍在）。
- **行为变化**：开局国家数等于城镇数（最多三个）；一句话建世界不再把村庄数提高到 3；任意编号的国家都升旗。
